# 事務職員役で画面を試す

IT に詳しくない事務職員の役（`eval/clerk-personas.ts`）が、実際の画面を Playwright MCP で操作して問診を最後まで進め、報告を返す。役も Claude なので、本物の事務職員と同じ感じ方とは限らない。結果はそう断ってから使う。

## 1. 準備

1. `npm run build` で本番ビルドを作る
2. 手元の本番サーバーを起こす。`.claude/launch.json` の `prod`（ポート 3100、試験用の合言葉つき）を、Browser pane の `preview_start` で起こす。ビルドし直したら、サーバーも起こし直す
3. 動かす役を決める。`eval/clerk-personas.ts` の `PERSONAS` から、変えた画面に関係する項目の役を選ぶ。全項目を見るときは全員

## 2. 動かす

- 1人ずつ：`npm run eval:clerk -- --persona <id> --url http://localhost:3100 --code <試験用の合言葉>`
- 何人か同時に動かすときは、バックグラウンドで並べてよい（ブラウザは役ごとに別）。終わりを知らせてもらい、途中で何度も様子を見ない
- 合言葉は `.claude/launch.json` の手元の試験用だけを使う。公開サイトの合言葉は使わない。録画や README に合言葉を出さない
- 結果は `eval/runs/clerk-<日時>-<id>/`（`report.json` と `tools.log`。手元だけで、コミットしない）

## 3. まとめる

役ごとに `report.json` を読み、次の表を作る。数字は報告と `summary` の値だけを使い、推測で埋めない。

| 役 | 項目 | 最後まで進んだか | 状態の一致（合った数／比べた数） | 時間 | 費用 |
| --- | --- | --- | --- | --- | --- |

そのうえで、役をまたいで、次を数える。

- 詰まった所（`stuck`）：同じ所で詰まった役の数
- 分かりにくい言葉（`unclear_words`）と、答えにくい質問（`hard_questions`）
- 状態が本当の状態と違った観点：画面の読み取りの誤りか、役の答え方のせいかを、`tools.log` と報告の回答で確かめる

## 4. 直す候補を選んでもらう

- 2人以上が同じ所で詰まったものを先に並べ、どこを直すかの案を添える
- 1人だけの指摘は「様子見」として分けて並べる
- 判定や問診の指示（Claude への指示、固定データ）に関わる直しは、評価（`npm run eval`）が要ることを書き添える
- どれを直すかは作者が決める。勝手に直さない

## 5. 記録する

- `DEVLOG.md` に、動かした役、上の表、詰まった所の数、直したことと直さなかったこと、費用を書く。役も Claude であることを断る
- 実在の病院名、人名、勤務先は書かない
